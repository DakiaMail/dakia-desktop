# Dakia anonymous usage collector

This is a deliberately small, first-party Cloudflare Worker for Dakia's
optional anonymous usage statistics. It accepts one fixed JSON schema at
`POST /v1/usage`; no other route exposes data.

## Privacy properties

- The Worker stores neither the JSON request body nor request headers, IP
  address, email addresses, mailbox/account identifiers, custom hostnames,
  message data, or credentials.
- `rotating_install_token` is a fresh, 128-bit random token generated by the
  app for each calendar month. The collector salts and hashes it before it
  reaches D1; only that hash is kept, solely to ignore duplicate reports.
- Receipt hashes are deleted by the daily scheduled Worker task after 35 days.
  Counters are kept only in `monthly_usage_aggregates`.
- The Worker has `observability.enabled: false` and contains no `console`
  calls. Do not enable Workers Logs, Logpush, Tail Workers, request-body logs,
  or a third-party analytics SDK for this service.
- CORS and ingestion allow only the one configured `ALLOWED_ORIGIN`; there is
  no wildcard, origin-less ingestion, credentialed CORS, or public read
  endpoint.
- A Workers Rate Limiting binding receives only a salted one-way digest of the
  source address, permits 20 attempts per minute per digest, and keeps no value
  in D1. It is an approximate abuse boundary, not an analytics signal.

This does not make Cloudflare disappear from the HTTPS path: its edge receives
the network connection. The Worker reads Cloudflare's source-address header
only to derive the transient salted rate-limit key; it never persists or logs
the address or key, and D1 does not contain either value.

## Accepted request schema

Every key is required; extra keys are rejected. The current app submits:

```json
{
  "schema": 1,
  "month": "2026-08",
  "rotating_install_token": "0123456789abcdef0123456789abcdef",
  "app_version": "0.4.0",
  "os": "macos",
  "os_version": "15.6",
  "arch": "arm64",
  "providers": ["fastmail", "gmail"]
}
```

`month` must be the current UTC month or immediately preceding month.
Providers are a sorted, unique set from `fastmail`, `gmail`, `icloud`, `other`,
`outlook`, and `yahoo`. The service stores the set as a single aggregate
dimension, never the individual account count.

## Local checks

Install the service-local developer dependencies, then run:

```sh
npm install
npm test
npm run types
npm run report
```

`npm run types` generates Worker binding types from `wrangler.jsonc` before
type-checking; do not hand-maintain an `Env` interface. The generated files and
service-local dependencies are ignored by Git.

## Provisioning (requires separate production approval)

No deployment or Cloudflare-account action is performed by this repository.
Before deployment, create a **new** database with its jurisdiction set at
creation time:

```sh
npx wrangler d1 create dakia-usage-analytics --jurisdiction=eu
```

Copy the database ID into `wrangler.jsonc`, then configure the hash salt as a
Worker secret (never in the config file):

```sh
npx wrangler secret put TOKEN_HASH_SALT
npx wrangler d1 migrations apply dakia-usage-analytics --remote
npx wrangler deploy --dry-run
```

Only after review of that dry run, bind `analytics.dakiamail.com` to this
Worker, configure `ALLOWED_ORIGIN` to the production Tauri origin, and deploy.
D1's `eu` jurisdiction constrains where D1 runs and persists data; it does not
by itself constrain where Workers receive requests. Evaluate Cloudflare
Regional Services separately if request handling must also be region-limited.

Retention and reporting controls are operational requirements: run the daily
receipt cleanup, retain aggregate counters for no more than 24 months, and do
not expose a version/provider bucket with fewer than 20 reports. The private
`queries/monthly-summary.sql` report enforces that bucket threshold and no
public reporting endpoint exists.
