# Native WebKit resource collector

This collector reads resources for one already running approved fictional Dakia
candidate. It never launches, controls, signals, swaps, registers, or stops an
application. Run unit and integration verification first. Follow
`docs/tauri-dev-ui-verification.md` before native collection and reuse the existing
approved application record. Do not create a new application identity.

The collector reports exact RSS and open file-descriptor observations for its
stable main PID. macOS does not expose a supported complete arbitrary WKWebView
process cohort API. The optional private responsible-process SPI can positively
attribute some observed WebKit processes, which remain a lower bound. Missing
SPI, permission errors, changing PID censuses, ambiguous responsibility, or no
positive mappings yield unavailable values. They never become numeric zero.
Per-process metrics are collected sequentially. For metric-definition version 4,
`aggregate` RSS and FD values are the maximum individual process observations,
which conservatively bound the sample-window peak. They are deliberately not a
sum that could combine mutually exclusive process peaks. The concurrent-process
count lower bound is one when any process was positively observed; the full list
of observed identities is retained separately. Below-ceiling lower bounds cannot
establish a pass; above-ceiling individual observations fail the whole-cohort
ceiling. These are sample-window bounds, not a simultaneous full-cohort snapshot.

## Offline verification

```sh
node --test scripts/native-webkit-resource-collector.node-test.mjs
python3 scripts/native-webkit-resource-collector.test.py
```

These tests use fictional files and mocked libproc/responsibility functions.
They do not enumerate live processes or launch/control Dakia. They cover identity
and source mutations, stale webview evidence, candidate resource changes, PID
reuse/ownership transitions, process-census failures, and the lower-bound rules.

## Prepare retained inputs

Use a fresh private directory under `/private/tmp`, mode `0700`. JSON inputs must
be canonical absolute paths to regular files owned by the current user with mode
`0600`. SHA-256 pins refer to exact file bytes, including whitespace. Outputs are
created exclusively with mode `0600`; no existing evidence is overwritten.

Write `.dakia-l013-owned-run.json` in that directory:

```json
{
  "schemaVersion": 1,
  "purpose": "dakia-native-l013-resource-v1",
  "runId": "<fresh UUID v4>",
  "runRoot": "<canonical private run directory>",
  "ownerUid": 501
}
```

Use the actual current UID. The marker only owns the resource evidence directory;
it does not authorize creating an application identity.

Retain the current governed source manifest generated by the programme. It has
`algorithm`, `digest`, `fileCount`, and `files` rows with `path`, `state`, `bytes`,
and `sha256`. Live collection recomputes its path/content digest, verifies the
listed source bytes, and compares it with `run-mail-safety.mjs`'s full current
`sourceSnapshot()`. A valid subset cannot hide additional governed files. Run
the collector from that exact checkout. It contains no dated source digest or
file count.

Copy the active `.approved-native-identity-swap.json` to the resource evidence
directory while the approved candidate is installed. Retain its hash and its
original active path. This allows summary generation after the guarded harness
has restored the original app and removed its active journal. Do not fabricate a
journal or bypass the approved replacement/recovery harness.

Capture a native accessibility observation of the actual running webview only
after separately proving its executable path and start identity. Retain the
underlying accessibility evidence with the run. A webview evidence JSON contains:

```json
{
  "schemaVersion": 1,
  "method": "native-accessibility-tree",
  "pid": 4242,
  "startTimeMicros": "<libproc process start time in Unix microseconds>",
  "executablePath": "<approved application>/Contents/MacOS/dakia-desktop",
  "executableSha256": "<current executable hash>",
  "webviewUrl": "tauri://localhost/",
  "observedAt": "<UTC ISO timestamp of the actual observation>"
}
```

Use `http://127.0.0.1:1420/` only for live Vite dev evidence. Packaged
`tauri://localhost/` observations remain packaged acceptance. The collector
validates a supplied observer receipt; it does not independently inspect the UI
or prove that the observer performed the recorded action. Never create such a
receipt from an assumed URL. Each live sample needs an observation at most 120
seconds old, after the process start, and not from the future.

The resource runtime manifest is a retained input, separate from attachment or
schema acceptance manifests. Its shape is:

```json
{
  "schemaVersion": 1,
  "purpose": "dakia-native-resource-runtime-v1",
  "runId": "<same UUID as owner marker>",
  "runRoot": "<resource run root>",
  "ownerMarkerSha256": "<owner marker hash>",
  "source": {
    "root": "<current checkout>",
    "digest": "<governed source digest>",
    "fileCount": 1,
    "manifest": { "path": "<retained source manifest>", "sha256": "<hash>" }
  },
  "approvedIdentity": {
    "path": "<existing approved root>/approved-native-identity.json",
    "sha256": "<sealed original identity record hash>"
  },
  "candidateTransaction": {
    "path": "<retained copy of candidate transaction>",
    "sha256": "<copy hash>",
    "activePath": "<approved root>/.approved-native-identity-swap.json"
  },
  "application": {
    "path": "<same approved application path>",
    "bundleIdentifier": "<same approved bundle identifier>",
    "executable": "<same application>/Contents/MacOS/dakia-desktop",
    "executableSha256": "<candidate executable hash>"
  },
  "process": { "pid": 4242, "startTimeMicros": "<actual Unix microseconds>" },
  "webviewEvidence": {
    "path": "<initial native observation>",
    "sha256": "<hash>"
  }
}
```

Use the actual file count and process identity. Live validation requires the
active journal to match the retained copy, its sealed original inventory to bind
the approved identity, and its candidate desktop hash to match the runtime. It
also recomputes the complete current candidate bundle inventory using the
approved transaction's traversal/digest convention, checks the structured plist
name/identifier, and rejects any process that started before the candidate
transaction's `createdAt`. This collector binds declared current source to an
observed runtime; retain the separate build/source-equivalence receipt as well.
It does not compile the app or independently prove compiler provenance.

Retain a limits JSON bound to the same run before collecting samples:

```json
{
  "schemaVersion": 1,
  "purpose": "dakia-native-l013-limits-v1",
  "runId": "<same UUID>",
  "maxMainRssBytes": null,
  "maxMainOpenFileDescriptors": null,
  "maxMappedWebKitAggregateRssBytes": null,
  "maxMappedWebKitAggregateOpenFileDescriptors": null,
  "maxMappedWebKitChildren": null,
  "regressionThresholdPercent": 20
}
```

Replace limits with predeclared positive integer ceilings when applicable.
`null` means observed without a ceiling, never a pass. Existing historical
baselines are preserved. This collector performs no historical 20% regression
comparison because a compatible baseline is not established here.

## Collect one sample per planned phase

Substitute existing input paths and exact hashes in these commands. CLI values
are individual arguments, so quote paths. No credentials are read.

```sh
node scripts/native-webkit-resource-collector.mjs sample \
  --run-root "$RESOURCE_ROOT" \
  --runtime-manifest "$RUNTIME_MANIFEST" --runtime-manifest-sha "$RUNTIME_SHA" \
  --webview-evidence "$FRESH_WEBVIEW_PROOF" --webview-evidence-sha "$WEBVIEW_SHA" \
  --limits "$LIMITS" --limits-sha "$LIMITS_SHA" \
  --phase foreground-before --output "$RESOURCE_ROOT/foreground-before.json"
```

The initial manifest webview receipt is the default if the override is omitted.
Use a new retained observation for later phases without rewriting the runtime
manifest. Verify exact main PID/path/start/UID both before and after collection.
Sampling never relies on a display name or a parent-child process tree. Numeric
PIDs are enumerated; unrelated command lines, environments, and file descriptors
are not read or persisted. Main and WebKit helper processes each have a 10-second
subprocess deadline and 4 MiB output cap; structured plist parsing has a 5-second
limit. Governed-source enumeration has a 10-second subprocess deadline. Bundle
inventory has a 10-second checked budget, 20,000 entries and 2 GiB maximum file
bytes. A failure records no successful sample; retain the command error.

Sample command exit `0` means acquisition completed, not that all resource
criteria passed. Exit `2` means a declared ceiling failed. Validation/collection
errors are nonzero; unsupported platforms return `69`.

## Summarize the exact planned observations

Prepare a sample list in the resource directory. `identity` is the pinned
resource runtime manifest. Declare the phase plan before collection and do not
add retries or reduce expected counts to hide a failed observation.

```json
{
  "schemaVersion": 1,
  "purpose": "dakia-native-l013-sample-list-v1",
  "runId": "<same UUID>",
  "identity": { "path": "<runtime manifest>", "sha256": "<hash>" },
  "limits": { "path": "<limits JSON>", "sha256": "<hash>" },
  "phasePlan": [{ "phase": "foreground-before", "exactSamples": 1 }],
  "samples": [{ "path": "<sample JSON>", "sha256": "<hash>" }],
  "historicalBaseline": null
}
```

```sh
node scripts/native-webkit-resource-collector.mjs summarize \
  --run-root "$RESOURCE_ROOT" \
  --sample-list "$SAMPLE_LIST" --sample-list-sha "$SAMPLE_LIST_SHA" \
  --output "$RESOURCE_ROOT/resource-summary.json"
```

Summaries recompute metrics, threshold outcomes, phase counts, identity and
provenance from pinned inputs. They do not need the app running or its active
journal when a retained journal copy is supplied. Keep the approved identity
record and all source/webview/transaction evidence available. Exit `2` means
failed; exit `3` means unavailable/unassessable WebKit scope. There is no full
WebKit resource pass path. Main-process ceiling results remain separately
reported. These bounded snapshots do not establish a long-term leak, soak,
foreground responsiveness, release, or physical sleep/wake pass.
